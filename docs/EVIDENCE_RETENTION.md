# Evidence retention policy

**Status:** `CURRENT_DOC`. Established 2026-09-28 as the safe, non-destructive part of audit finding F-003 (committed evidence mass). No evidence was deleted, moved, compressed, or pruned to create this document.

**Owner:** Sky. Deleting unique evidence is an owner decision; this policy states the prerequisites, it does not authorize removal.

---

## 1. Why this exists

The repository keeps its evidence beside its receipts rather than deleting it. That doctrine is deliberate and stays: a dated receipt is true for its own date and is never rewritten. The cost is mass. At 2026-09-28 the tracked evidence estate is large (see the [candidate census](../qa-reports/evidence-retention/2026-09-28_EVIDENCE_RETENTION_CANDIDATES.md)). This policy keeps the doctrine while giving the owner a safe, reproducible way to decide what may later be retired.

## 2. Scope

| Surface | Role | Default disposition |
|---|---|---|
| `qa-reports/` dated receipts and phase evidence | Release evidence and raw captures cited by receipts | Retain |
| `design-reviews/` dated programs | Historical receipts and their raw evidence | Retain |
| `summaries/` | June 2026 pass reports and emails | Retain |
| `cinematic-masters/` | Regeneration masters for the protected cinematic scene (never shipped) | Retain |
| `public/` | Shipped assets the site serves | Retain; governed by `validate-assets.mjs` |

## 3. Retention classes

- `AUTHORITATIVE_CURRENT` — shipped assets and current source. Never a deletion candidate.
- `RELEASE_EVIDENCE` — receipts, candidate SHA/tree records, gate evidence. Never a deletion candidate.
- `HISTORICAL_RECEIPT` — dated review programs and pass reports. Retain as provenance.
- `REGENERATION_MASTER` — the cinematic masters. Regenerable in principle, expensive and machine-bound in practice; treat as retained.
- `GENERATED_EXPIRED` — generated output past its validity window. A possible candidate, owner-gated.

## 4. Forward rule (new evidence)

Carried from `qa-reports/INDEX.md` and made explicit here:

1. Name a new receipt `YYYY-MM-DD_<Topic>.md` under `qa-reports/`.
2. **Cite by hash, do not duplicate.** When a new artifact would be byte-identical to one already tracked, cite the existing path and its SHA-256 instead of committing another copy, unless a self-contained package or a genuine before/after comparison needs the copy.
3. **Store review-grade evidence.** Future visual evidence is captured at review grade, not the largest available resolution, so the estate does not grow faster than it needs to.
4. Regenerate `qa-reports/INDEX.md` (`npm run qa:index`) after staging new evidence.

## 5. Deletion prerequisites

A file may be removed only when **all** of the following hold, and only in a dedicated, bounded task:

1. **Owner authorization** for that specific removal is recorded (`OWNER_AUTHORIZATION_REQUIRED_FOR_IRREVERSIBLE_EVIDENCE_REMOVAL`).
2. The path is **not cited** by any receipt or manifest that remains.
3. The content is **preserved in git history**: no history rewrite, no force-push, no filter-branch.
4. A **manifest of kept and dropped paths with SHA-256** is committed with the removal.
5. The change is **isolated**: no evidence retirement is mixed with feature, design, or tooling work.
6. The removed file is not the only copy of unique evidence, is not a `RELEASE_EVIDENCE` receipt, and is not a lifecycle banner.

Not permitted at any time: rewriting a dated receipt, deleting a receipt, deleting the only copy of evidence, or reducing the estate merely to make the repository look smaller.

## 6. Reproducing the census

The candidate census is a point-in-time artifact, regenerated by read-only commands (no dependencies):

```bash
# every tracked file in the evidence estate
git ls-files qa-reports design-reviews cinematic-masters summaries

# large files (>500 KB) with sizes
git ls-files -z qa-reports design-reviews cinematic-masters summaries \
  | xargs -0 stat -f '%z %N' | awk '$1 > 512000' | sort -rn

# exact duplicates by content hash
git ls-files -z qa-reports design-reviews cinematic-masters summaries \
  | xargs -0 shasum -a 256 | sort | awk '{print $1}' | uniq -d
```

`shasum` is the macOS spelling; use `sha256sum` elsewhere. The [candidate census](../qa-reports/evidence-retention/2026-09-28_EVIDENCE_RETENTION_CANDIDATES.md) records the totals those commands produced on 2026-09-28.
