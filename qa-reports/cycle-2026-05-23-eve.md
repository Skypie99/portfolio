**NEW-2. Steve's hosting stance — stay on GH Pages + meta-CSP, or migrate to Cloudflare Pages.** **[DECIDE]**
- GH Pages doesn't support custom HTTP response headers. That kills real CSP, HSTS, X-Frame-Options, X-Content-Type-Options.
- Steve recommends: **stay on GH Pages for v1**, add a meta-tag CSP in `app/layout.tsx` (covers script-src, style-src, img-src, frame-ancestors-via-X-Frame-Options-fallback, etc.). Real headers wait until v2.
- Migration alternative: Cloudflare Pages (free, supports `_headers` file) — Rory would re-author `deploy.yml`, ~1 cycle of work.
- **Recommendation: stay-for-v1.** Portfolio is static, no auth/forms/cookies, real-world exploit surface is near-zero. Revisit in Cycle 5+.

**NEW-3. Accept 2 remaining moderate `postcss` CVEs.** **[ACCEPT or override]**
- After upgrading `next` 15.1.4 → 15.5.18 (Steve's P0, applied this cycle), `npm audit --omit=dev` drops from 1 critical + 9 high + 1 moderate → **0 critical, 0 high, 2 moderate**.
- The 2 remaining are both transitive `postcss` issues inside Next 15.5's build pipeline. Only fixable by downgrading Next to 9.x (unacceptable — loses App Router, loses every Cycle 2/3 feature).
- PostCSS runs at build time only; output is static CSS. Zero runtime exposure on GH Pages.
- **Recommendation: accept** with a one-line note in README. Re-evaluate when Next 15.6+ ships with a patched transitive.

**NEW-4. Sidebar breakpoint — Tailwind `md:` (768px) shipped vs Dani's spec (960px).** **[CONFIRM 768 or revert to 960]**
- Shamus used Tailwind's default `md:` (768px) for the sidebar show/hide. Dani's PROJECT_DESIGN §3.4 spec was 960px.
- Alex's F-1: between 768–960px the sidebar (280px) crowds the main column (~488px before gutters). Not WCAG-failing; layout-density concern only.
- **Recommendation: confirm 768px (tablet-friendly).** Modern phones are 414–428px CSS-px; modern tablets land at 768–1024px portrait. 768 gives sidebar earlier on landscape phones / portrait tablets, which most personas (Maya/Daniel) likely use. If Sky prefers 960, Shamus adds a custom `nav: 960px` Tailwind breakpoint — 1-line config change + 2 component edits.

**NEW-5. Disabled-button color spec (Dani vs Alex).** **[PICK A or B]**
- Dani spec'd `text-pebble` (`#B8B8AA`) for disabled buttons. WCAG-exempt (disabled state) but renders at 1.90:1 — visually illegible.
- Alex's alternative: `text-charcoal` at 50% opacity = ~4.3:1 — still clearly disabled, still readable.
- **Recommendation: Alex's `text-charcoal 50%`.** Editorial restraint matters, but a disabled button no one can read is a usability cliff. No callers exist yet — pick now, lock the spec, before Cycle 6's contact form ships.

1. Open in a browser. Page should land on cream `#FAF9F5` with Cormorant Light hero text.
