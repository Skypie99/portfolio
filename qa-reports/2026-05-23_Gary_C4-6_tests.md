## ProjectCard coverage detail

1. **Renders title, role, year from props** — uses `getByRole('heading', { level: 2 })`
   for the title and a function matcher for the "Role · Year" metadata line so the
   test won't break if Shamus tweaks the middot separator.
2. **Whole card is one link to `/work/<slug>/`** — asserts exactly one `<a>`
   per card and the trailing-slash convention matches the static-export setup.
3. **Accessible name summarises destination** — `getByRole('link', { name: ... })`
   with a regex covering title + role + year (Alex §4.4 — link text meaningful
   out of context).
4. **Featured visual treatment** — uses `rerender` to flip `featured: false → true`
   on the same fixture and asserts the "Featured" pill only renders in the
   true state. (The terracotta indicator dot is `aria-hidden`, so the assertion
   targets the text label, which is what a screen-reader user actually hears.)

## content.ts coverage detail

1. **`getProfile()` returns ProfileSchema-valid data** — uses `safeParse` not `parse`
   so the failure mode is a readable Vitest diff, not a thrown ZodError.
2. **`getDeliverables()` returns array of valid Deliverables** — iterates and
   re-parses each row, with a `.toBe(true, \`deliverable ${d.id} failed schema\`)`
   message so a regression points Sky straight at the offending row.
3. **Deliverables ordered newest-first by year** — covers the sort contract
   the loader documents, without baking in specific IDs.
4. **`getCertificates()` returns array of valid Certificates** — same
   iterate-and-re-parse pattern as deliverables.
5. **`getFeaturedDeliverable()` returns the featured deliverable** — non-null
   in the current ship state, `.featured === true`.
6. **`getFeaturedDeliverable()` agrees with the full-list filter** — guards
   against the helper drifting from the underlying source of truth.
7. **Featured-slot invariant: exactly one featured** — Dana's DATA_SHAPE.md §6
   rule. Reads the real `content/deliverables.json`, so editing the JSON to
   feature two (or zero) deliverables fails this test locally before the Next
   build catches it in CI. This is the highest-leverage protection in the file.

## Notes / things Sky should know

- **`content.test.ts` is non-hermetic by design.** It reads the real JSON files
  so it doubles as a build-time invariant check. If Sky edits `content/` and
  breaks the schema or the featured-slot rule, `npm run test` catches it before
  `npm run build` does. This is the highest-value test in the file.
- **`ProjectCard.test.tsx` IS hermetic** — fixture lives in the test file.
  Renaming a deliverable or shuffling JSON does not break it.
- **`rerender` over two separate `render` calls** in the featured-pill test —
  cleaner diff, proves the only difference is the `featured` boolean.
